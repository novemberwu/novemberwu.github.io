SESSION 1

Instance Variables

The state of an object — and how we declare it.

To create a data type, you need to provide code that

  • Defines the set of values (instance variables)
  • Implements operations on those values (methods)
  • Creates and initializes new objects (constructors)

Instance variables — declarations associate variable names with types; set of type values is “set of values”.
Methods — like static methods; can refer to instance variables.
Constructors — like a method with the same name as the type; no return type declaration; invoked by new, returns object of the type.

Instance variable syntax

private [final] data_type name;
  • usually private
  • final — if the field is immutable: primitive types such as int, double, etc., or immutable reference types such as String

Instance variables

  • Belong to objects: instance variables are not shared among all objects of a class; each object possesses its own set of instance variables. Changes made in one object do not affect the same variable in other objects.
  • Define object state: they represent the state or properties of an object.
  • Declaration: declared directly within the class body, but not within any method, constructor, or static block.

SESSION 2

Access Modifiers & Encapsulation

Protecting the state — who is allowed to touch it?

Class’s client

  • Any class that uses class X is called a client of X
  • Client can only access the public methods and variables of class X
Class X
private fields

public constructor(s)  ← client may call

public methods  ← client may call

private methods
←
Class Y — a client of X
Constructs objects of X and/or calls X’s public methods.

Everything else: compiler error.

Public vs. Private

  • Public constructors and methods of a class constitute its interface with classes that use it — its clients.
  • All instance variables are usually declared private — they are hidden from clients.
  • Static constants occasionally can be public.
  • “Helper” methods that are needed only inside the class are declared private.

Public vs. Private — inside the same class

  • A private field is accessible anywhere within the class’s source code.
  • Any object can access and modify a private field of another object of the same class.
public class Fraction {
    private int num, denom;
    ...
    public Fraction multiply(Fraction other) {
        int newNum = num * other.num;   // other is private too - OK!
        ...
    }
}

Getter and Setter

  • Methods that return values of private fields are called accessors (get...).
  • Methods that set values of private fields are called modifiers / mutators (set...).
  • These are not precise categories: the same method can modify several fields, or modify a field and also return its old or new value.
public int getRating() { return this.rating; }
public void setText(String t) { this.text = t; }

Encapsulation

  • Hiding the implementation details of a class (making all fields and helper methods private) is called encapsulation.
  • Encapsulation helps in program maintenance: a change in one class does not affect other classes.
  • A client of a class interacts with the class only through well-documented public constructors and methods; this facilitates team development.

Encapsulation — what the class looks like

public class MyClass {
    private sometype myField;              // Private fields: hidden

    public MyClass (...) { ... }           // Public interface:
    public sometype myMethod (...) { ... } //   public constructors and methods

    private sometype myMethod (...) { ... }// Private helpers: hidden
}

The public interface — public constructors and methods — is the only door into the class.

SESSION 3

Constructors

Creating and initializing objects — new, overloading, copy constructors, this().

Constructors

  • A constructor is a procedure for creating objects of the class.
  • A constructor often initializes an object’s fields.
  • Constructors do not have a return type (not even void) and they do not return a value.
  • All constructors in a class have the same name — the name of the class.
  • Constructors may take parameters.

Constructors (continued)

  • If a class has more than one constructor, they must have different numbers and/or types of parameters.
  • Programmers often provide a “no-args” constructor that takes no parameters (a.k.a. arguments).
  • If a programmer does not define any constructors, Java provides one default no-args constructor, which allocates memory and sets fields to the default values.

Example 3: Fraction’s four constructors (1 of 2)

Solution: one class, four ways to create a Fraction — note the validation and the exception.

public class Fraction {
    private int num, denom;

    public Fraction() {          // no-args
        num = 0; denom = 1;
    }
    public Fraction(int n) {
        num = n; denom = 1;
    }
    public Fraction(int n, int d) {
        if (d != 0) {
            num = n; denom = d;
            reduce();
        } else {
            throw new IllegalArgumentException(
                "Fraction construction error: denominator is 0");
        }
    }

    public Fraction(Fraction other) {  // copy
        num = other.num;
        denom = other.denom;
    }

Example 3: Fraction’s four constructors (2 of 2)

Constructors of a class can call each other using the keyword this — a good way to avoid duplicating code.

public Fraction(int n) {
    this (n, 1);
}
public Fraction(int p, int q) {
    num = p;
    denom = q;
    reduce ();
}

Operator new

  • Constructors are invoked using the operator new.
  • Parameters passed to new must match the number, types, and order of parameters expected by one of the constructors.
Fraction f1 = new Fraction ();
Fraction f2 = new Fraction (5);      // 5 / 1
Fraction f3 = new Fraction (4, 6);
Fraction f4 = new Fraction (f3);     // copy constructor

You must create an object before you can use it

private Fraction ratio;              // ratio is set to null

ratio = new Fraction (2, 3);         // now ratio refers to a valid object

ratio = new Fraction (3, 4);         // now ratio refers to another object
                                     // (the old object is "garbage-collected")

References to objects

Fraction f1 = new Fraction(3,7);
Fraction f2 = f1;
f1 and f2
Refer to the same object — one object, two names.
Fraction f1 = new Fraction(3,7);
Fraction f2 = new Fraction(3,7);
f1 and f2
Two different objects that happen to hold equal values.

SESSION 4

Methods, return & Scope

What an object can do — and where variables are visible.

Methods

public [or private] returnType
    methodName (type1 name1, ..., typeN nameN)
{
    ...   // Body
}
  • To define a method:
    • decide between public and private (usually public)
    • give it a name
    • specify the types of parameters and give them names
    • specify the method’s return type or choose void
    • write the method’s code

Methods (rules)

  • A method is always defined inside a class.
  • A method returns a value of the specified type unless it is declared void.
  • The return type can be any primitive data type or a class type.
  • A method’s parameters can be of any primitive data types or class types.
  • Empty parentheses indicate that a method takes no parameters: public [or private] returnType methodName ()

Methods — Java style

  • A method name starts with a lowercase letter.
  • Method names often sound like verbs.
  • A method that returns the value of a field often starts with get: getWidth, getX.
  • A method that sets the value of a field often starts with set: setLocation, setText.

return statement

  • A method, unless void, returns a value of the specified type to the calling method.
  • The return statement is used to immediately quit the method and return a value. The type of the return value must match the method’s declared return type.
return expression;

return — class types

  • If its return type is a class, the method returns a reference to an object (or null).
  • Often the returned object is created in the method using new. The returned object can also come from a parameter or from a call to another method.
public Fraction inverse() {
    if (num == 0)
        return null;
    return new Fraction (denom, num);
}

return — several return statements

  • A method can have several return statements; then all but one of them must be inside an if or else (or in a switch):
public someType myMethod (...)
{
    ...
    if (...)
        return <expression1>;
    else if (...)
        return <expression2>;
    ...
    return <expression3>;
}

return — boolean methods

  • A boolean method can return true, false, or the result of a Boolean expression:
public boolean myMethod (...)
{
    ...
    if (...)
        return true;
    ...
    return n % 2 == 0;
}

return — void methods

  • A void method can use a return statement to quit the method early. (No need for a redundant return; at the end.)
public void myMethod (...)
{
    ...
    if (...)
        return;
    ...
}

Scope and access

  • Local variables are variables declared in the headers and bodies of blocks of code.
  • Local variables can only be accessed in the block in which they are declared.
  • When there is a local variable or parameter with the same name as an instance variable, the name refers to the local variable.
  • Local variables declared inside a method cannot be declared as public or private.

Static & Parameter Passing

Class-level state, and what really gets copied when you call a method.

Static variables

  • A static variable, also known as a class variable, is associated with the class, not with individual objects of the class.
  • There is only one copy of a static variable, shared among all instances of the class.
  • They can be accessed directly using the class name (e.g., ClassName.variableName) without requiring an object instance.
  • Commonly used for constants or values that should be shared by all objects of a class.

Static methods

  • A static method belongs to the class, not to an object instance.
  • Called directly using the class name (e.g., ClassName.methodName()) without creating an object.
  • Static methods can only access other static members directly. They cannot directly access non-static instance variables or methods — those require an object instance to exist.
  • Often used for utility functions or helpers that are independent of any specific object’s state.

Passing parameters — any expression works

Any expression that has an appropriate data type can serve as a parameter:

double u = 3, v = -4;
...
Polynomial p = new Polynomial (1.0, -(u + v), u * v);
double y = p.getValue (2 * v - u);
public class Polynomial {
    public Polynomial (double a, double b, double c) { ... }
    public double getValue (double x) { ... }
    ...
}

Passing parameters — promotion

  • A “smaller” type can be promoted to a “larger” type (for example, int to long, float to double).
  • int is promoted to double when necessary:
...
Polynomial p = new Polynomial (1, -5, 6);   // same as (1.0, -5.0, 6.0)
double y = p.getValue (3);                 // same as (3.0)

Example 5: static & parameter passing (2 of 3)

Solution: primitives are always passed by value — the value is copied into the parameter.

double x = 3.0;
double y = p.getValue ( x );
// x: 3.0 --copy--> u: 3.0
// u acts like a local variable
public class Test {
    public double square (double x) {
        x *= x;          // x here is a COPY
        return x;
    }
    public static void main(String[] args) {
        Test calc = new Test ();
        double x = 3.0;
        double y = calc.square (x);
        System.out.println (x + " " + y);
    }
}

Output: 3.0 9.0 — the original x is unchanged.

Example 5: static & parameter passing (3 of 3)

Solution: objects are always passed as references — the reference is copied, not the object.

Fraction f1 = new Fraction (1, 2);
Fraction f2 = new Fraction (5, 17);

Fraction f3 = f1.add (f2);
public class Fraction {
    ...
    public Fraction add (Fraction f) {
        ...
    }
}

Parameter f receives a copy of the reference — it refers to the same object as f2 (num = 5, denom = 17).

  • A method can change an object passed to it (it gets a reference to the original object).
  • A method can change the object for which it was called (this object acts like an implicit parameter): panel.setBackground(Color.BLUE);

Overloading & this

Finishing touches — then a full FRQ.

Overloaded methods

  • Methods of the same class that have the same name but different numbers or types of parameters are called overloaded methods.
  • Use overloaded methods when they perform similar tasks:
public void move (int x, int y)        { ... }
public void move (double x, double y)  { ... }
public void move (Point p)             { ... }

public Fraction add (int n)            { ... }
public Fraction add (Fraction other)   { ... }

How the compiler picks one

  • The compiler treats overloaded methods as completely different methods.
  • The compiler knows which one to call based on the number and the types of the parameters passed to the method.
Circle circle = new Circle(5);
circle.move (50, 100);

Point center = new Point(50, 100);
circle.move (center);
public class Circle {
    public void move (int x, int y) { ... }
    public void move (Point p)      { ... }
    ...
}

Return type alone is not enough

The return type alone is not sufficient for making a distinction between overloaded methods:

public class Circle {
    public void move (int x, int y)   { ... }
    public Point move (int x, int y)  { ... }   // compile error!
    ...
}

The this keyword

  • In Java, this is a keyword that refers to the current object — the object whose method or constructor is being executed.
  • Four common uses — Example 6 walks through all of them.

Example 6: the four uses of this (1 of 4)

Solution: using this to refer to current class instance variables.

class Geeks {
    int a;
    int b;

    Geeks(int a, int b) {
        this.a = a;      // this.a = field,  a = parameter
        this.b = b;
    }
    void display() {
        System.out.println("a = " + a + "  b = " + b);
    }
    public static void main(String[] args) {
        Geeks object = new Geeks(10, 20);
        object.display();          // a = 10  b = 20
    }
}

Example 6: the four uses of this (2 of 4)

Solution: using this() to invoke the current class constructor.

Geeks() {
    this(10, 20);              // calls the constructor below
    System.out.println("Inside  default constructor \n");
}

Geeks(int a, int b) {
    this.a = a;
    this.b = b;
    System.out.println("Inside parameterized constructor");
}

public static void main(String[] args) {
    Geeks object = new Geeks();
}
// Output: Inside parameterized constructor
//         Inside  default constructor

Example 6: the four uses of this (3 of 4)

Solution: using this as a method parameter.

Geeks() { a = 10; b = 20; }

void display(Geeks obj) {
    System.out.println("a = " + obj.a + "  b = " + obj.b);
}

void get() {
    display(this);             // pass myself along
}

public static void main(String[] args) {
    Geeks object = new Geeks();
    object.get();              // a = 10  b = 20
}

Example 6: the four uses of this (4 of 4)

Solution: using this to invoke the current class method.

void display() {
    this.show();               // calling function show()
    System.out.println("Inside display function");
}
void show() {
    System.out.println("Inside show function");
}
public static void main(String args[]) {
    Geeks g1 = new Geeks();
    g1.display();
}
// Output: Inside show function
//         Inside display function

Summary

  • Instance variables define an object’s state — usually private, final when immutable.
  • Encapsulation: clients interact only through the public interface.
  • Constructors create and initialize objects; they may overload, chain via this(...), and validate.
  • Methods return a value (or nothing); local variables shadow nothing but follow strict scope rules.
  • static belongs to the class; primitives are copied, objects’ references are copied.
  • Overloading differs by parameters, never by return type; this is the current object.
