## 2. 核心物理与数学

既然是物理模拟，数学公式肯定少不了。整个引擎的核心基于牛顿经典力学，虽然 CSA 不考微积分，但我们可以用离散化的方式来实现。

## 2.1 运动学基础
每一帧（Frame），我们都需要更新每个粒子的状态。就我们物理1学的牛二

$$\vec{a}_i = \frac{\vec{F}_{net}}{m_i}$$
更新速度 (其实就是积分一下，这里计算机近似直接乘上dt就行了):
$$\vec{v}_{i, t+1} = \vec{v}_{i, t} + \vec{a}_i \cdot \Delta t$$
更新位置 (说白了就是再积一次):
$$\vec{p}_{i, t+1} = \vec{p}_{i, t} + \vec{v}_{i, t+1} \cdot \Delta t$$
## 2.2 万有引力
应该计算量比较大...任意两个粒子之间都存在引力。
$$\vec{F}_{ij} = G \frac{m_i m_j}{|\vec{r}|^2} \cdot \hat{r}$$
为了代码实现方便，我们可以把单位向量 $\hat{r}$ 展开，避免开根号后再除一次：
$$\vec{F}_{ij} = G \frac{m_i m_j}{|\vec{r}|^3} \cdot \vec{r}$$

$G$: 引力常数（在这个虚拟宇宙里我可以随意设定，让引力更夸张一点）。$\vec{r}$: 从粒子 $i$ 指向粒子 $j$ 的位置向量 ($\vec{p}_j - \vec{p}_i$)。

## 2.3 碰撞检测
当粒子撞墙时，就让它反弹。这其实就是把速度向量在法线方向分量取反，并乘以一个恢复系数 (Restitution Coefficient) $e$ (0 到 1 之间，模拟能量损失)：
$$v_{perpendicular} = -e \cdot v_{perpendicular}$$
如果 $e < 1$，粒子跳几次就会停下来，非常真实。

## 3.2 性能优化与算法
最朴素的引力计算需要 $O(N^2)$ 的复杂度（每个粒子都要和所有其他粒子算引力）。如果有 1000 个粒子，那就是 $1,000,000$ 次计算每帧！电脑会炸的！

优化方案：多线程: 既然 Java 没法直接调 CUDA 跑 GPU，那我就榨干 CPU。使用 ExecutorService 把粒子数组切成小块，分给 CPU 的不同核心去算。Core 0 算粒子 0-250Core 1 算粒子 251-500...以此类推。

空间划分: 如果时间允许，我会写一个 四叉树（没搞懂是啥，ai说的）。只计算附近的粒子引力，忽略太远的，把复杂度降到 $O(N \log N)$。

## 3.3 图形界面
